# Проверка изменений P0 — 20.10.2026

Исходная точка: коммит `4386721`, 20 проходящих тестов. Проверки выполняются на временных базах и подменённых API, без публикации сообщений в живые группы и без изменения рабочей `.state`.

## P0.1 — карантин входных событий

Реализованы отдельная валидация полей, карантин выбранных групп, защита от повторов, повторная обработка сохранённого события и отображение проблем в статусе. Схема базы версии 1; перед миграцией старой базы создаётся согласованная резервная копия с правами 0600.

Проверки после изменения кода, до обновления документации:

- `python3 -m unittest discover -s 02-messenger-sync/poc -p 'test_*.py' -v`: **25 тестов, OK**.
- `python3 -m py_compile .../bridge.py .../test_bridge.py`: успешно.
- Отдельный прогон: пакет «корректное → картинка MAX без URL → корректное» принят дважды; получены две задачи, обе отправлены через подменённый API. После открытия базы заново сохранены курсор `123` и одна открытая проблема; `status` показывает её без текста сообщения.
- Регрессионные тесты проверяют откат задач, карантина и курсора при ошибке SQLite; неподавление программных ошибок; отсутствие архивирования чужого чата; восстановление карантина; миграцию без потери отправленных задач.

Ограничение: событие без определяемого чата не архивируется и не подтверждается. Повторная обработка после исправления обработчика может доставить сообщение позже новых сообщений. Живая проверка новых сценариев пока не выполнялась.

## P0.2 — управление очередью

Добавлены команды просмотра и разбора задач/карантина, состояние `skipped`, журнал `audit`, проверка ID найденной копии, обработка оставшихся частей сообщения. Изменения выполняются только при свободной блокировке процесса; просмотр использует read-only соединение. Схема базы версии 2; миграции сохраняют предварительную резервную копию.

Проверки после изменения кода, до обновления документации:

- Полный unittest-прогон: **36 тестов, OK**; проверка синтаксиса успешна.
- Отдельный прогон настоящего CLI через новые процессы на временной базе: подтверждение `uncertain`, повтор `failed`, пропуск трёх частей, повтор того же подтверждения и продолжение доставки через подменённый API.
- Итог: две отправленные задачи, три пропущенные части, пять записей аудита. Повтор подтверждения не добавил аудит или отправку.
- Автотесты проверяют запрет изменения `sending`, обязательное признание риска для повтора `uncertain`, уникальность ID копии, сохранение reply-связи и откат действия при ошибке записи аудита.
- Проверены запрет изменения при занятом `process.lock`, отсутствие сетевых вызовов в командах обслуживания и отсутствие текста переписки в выводе.

Ограничение: `confirm` фиксирует результат ручной сверки оператора и не проверяет существование копии сетевым запросом. Причины ручных решений хранятся в локальной таблице `audit`; в обычный вывод включены только метаданные действий.
