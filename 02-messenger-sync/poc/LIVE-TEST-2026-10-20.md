# Живой запуск обновлённого моста — 20.10.2026

После завершения P0.1–P0.3 пользователь попросил запустить мост для ручного теста и затем подтвердил: «работает».

## Что проверено при запуске

- `doctor` успешно обратился к живым API Telegram и MAX, проверил ожидаемых ботов, выбранные группы, права и отсутствие webhook-подписок.
- Запущен код коммита `7aa9489`; локальная база обновлена с версии 0 до версии 3. До миграции создана согласованная резервная копия с правами 0600; прежние отправленные задачи и связи ID сохранены.
- `health --json` подтвердил работающий процесс, свежий heartbeat и успешный опрос обеих платформ.
- Отдельно запущен локальный монитор с интервалом 5 секунд; события направляются в `.state/alerts.jsonl`. Внешний получатель не подключён.
- На снимке сразу после запуска в базе было по 12 задач `sent` в каждую сторону. После ручного теста — по 13, то есть по одной дополнительной успешно опубликованной копии в каждом направлении. Незавершённых задач, открытого карантина и проблем health на этом снимке нет.
- Пользователь подтвердил работу ручным тестом. Подробный перечень выполненных им сценариев не предоставлен; каждый пункт расширенного плана автоматически пройденным не считается.

Сводка собрана без публикации текстов сообщений, имён участников, токенов и приватных URL. База и логи остаются локально и в Git не включаются.

## Границы результата

Этот запуск подтверждает подключение обновлённого кода к двум тестовым группам, работу обмена и телеметрии. Он не подтверждает нагрузочную устойчивость, длительный простой, живую обработку каждого вида ошибки или внешнюю доставку оповещений. Детальные проверки P0 с подменёнными API записаны отдельно в [протоколе P0](P0-VALIDATION.md); базовые проверки фото и ответов — в [протоколе 19.10.2026](LIVE-TEST-2026-10-19.md).

На момент проверки мост и монитор работают как локальные фоновые процессы. Их PID и логи находятся в `.state/live-bridge.pid`, `.state/live-monitor.pid`, `.state/live-bridge.log`, `.state/live-monitor.log`. Это не системные службы и не серверное размещение; текущее состояние проверяется командой `health`, а не датой этого документа.
