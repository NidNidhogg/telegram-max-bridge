# Базовая живая проверка Telegram ↔ MAX — 19.10.2026

Это исторический протокол первичной проверки. После реализации P0.1–P0.3 обновлённый код запущен 20.10.2026 и подтверждён пользователем; актуальный результат — в [протоколе 20.10](LIVE-TEST-2026-10-20.md). Числа и ограничения ниже относятся к испытанию 19.10 и не подменяются результатами следующего дня.

Результат: собственный локальный мост передаёт обычный текст и картинки с подписями в обе стороны между двумя закрытыми тестовыми группами. Все исходные сообщения отправлены через пользовательский интерфейс от участника, копии — отдельными ботами. Рабочие группы и другой бот MAX не использовались.

## Подключение

| Площадка | Тестовый чат | Бот |
|---|---|---|
| Telegram | «Тест TG ↔️ MAX», `-1004490098913` | `@max_tg_2sync_bot` |
| MAX | «Тест TG ↔ MAX», `-80280477827835` | `@se14620006_1_bot` |

Telegram преобразовал исходную обычную группу `-5504246092` в супергруппу при назначении администратора. Событие `migrate_to_chat_id` подтвердило новый ID; конфигурация обновлена до запуска. У бота включён Privacy Mode, но роль администратора позволяет получать обычные сообщения. [Telegram FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get), [Message: migration](https://core.telegram.org/bots/api#message).

MAX: через API подтверждены `is_admin=true` и `read_all_messages`. Удаление сообщений, управление участниками и назначение администраторов отключены. Изменение сведений чата и закрепление интерфейс оставил как общие права участников; API также возвращает `can_call`. `write` не выдано: по актуальной документации в группах оно относится к редактированию/удалению, а обычная отправка в тесте работает без него. [Права ChatMember](https://dev.max.ru/docs-api/objects/ChatMember).

Токены находятся только в локальном `.env`, исключённом из Git, права 0600. В MAX включено добавление бота в групповые чаты. Webhook-подписок нет. TLS-проверка включена; дополнительный корневой сертификат ограничен SSL-контекстом MAX, как описано в README.

## Фактические проверки

| Сценарий | Результат |
|---|---|
| Обычный текст Telegram → MAX, без команды и упоминания | Копия появилась с именем автора и площадкой |
| Обычный текст MAX → Telegram | Копия появилась с именем автора и площадкой |
| PNG через интерфейс MAX → Telegram, с подписью | Фото 500×500 и подпись видны в Telegram |
| Картинка через интерфейс Telegram → MAX, с подписью | Фото и подпись видны в MAX |
| Ответ в MAX на копию первого сообщения Telegram | В Telegram получен настоящий reply к исходному сообщению; дополнительно имеется текстовая цитата |
| Ответ в Telegram на копию сообщения MAX | В MAX получен ответ, привязанный к исходному сообщению «какова цена курса по кремам?»; дополнительно видна текстовая цитата. Проверено на тестовых группах позднее в тот же день. |
| Перезапуск после первых трёх успешных доставок | Уже доставленные сообщения не отправлены заново; оставшаяся картинка доставлена после исправления |
| Отсутствие циклов | 5 исходных сообщений дали 5 заданий и 5 копий; собственные копии не породили новых заданий |
| Локальные тесты | 20 тестов прошли, включая повторные события, собственное эхо, ответы, очередь и неопределённый результат публикации |

Итог очереди после теста: `max sent 2`, `tg sent 3`; задач `pending`, `failed`, `uncertain` нет. Это наблюдение короткого теста, не гарантия при любых сбоях.

Обнаружена и исправлена ошибка: сервер файлов Telegram может возвращать картинку с `application/octet-stream`. Поддерживаемый формат теперь определяется по сигнатуре JPEG/PNG/WEBP; содержимое с неверной сигнатурой отклоняется. Картинка остановилась до публикации, поэтому её единственный повтор был безопасен. Добавлены два регрессионных теста.

## Что ещё не проверено живым экспериментом

- Альбомы, большие изображения и длинные тексты.
- Дополнительные человеческие участники, серии сообщений и нагрузка.
- Длительный простой, потеря сети, ограничения API и восстановление после аварии во время публикации.
- История для новичка, правки, удаления и сообщения сторонних ботов. Правки/удаления/импорт архива в коде не реализованы.

Локальные тесты некоторых из этих случаев не заменяют живую проверку. Полный план расширенного испытания остаётся в документе PoC.

## Как продолжить тест

Мост запущен локально. Можно писать обычные сообщения и отправлять фотографии в эти две группы. Компьютер должен быть включён, процесс — работать; автозапуск и серверное размещение не настроены. Сообщения появляются от бота с подписью исходного автора.

Проверка очереди из корня проекта:

```sh
rtk proxy python3 02-messenger-sync/poc/bridge.py status
```

После остановки повторный запуск:

```sh
rtk proxy python3 02-messenger-sync/poc/bridge.py run
```

Одновременно допускается один процесс. Это тестовая реализация с локальным хранением очереди, без автоматической очистки и без гарантии доставки при любых сбоях; использовать только тестовые данные.
