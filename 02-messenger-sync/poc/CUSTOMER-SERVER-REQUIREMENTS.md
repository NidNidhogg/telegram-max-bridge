# Требования к размещению моста Telegram ↔ MAX

Дата: 21.10.2026. Для размещения на сервере заказчика.

Сервис синхронизирует общение пользователей в группах Telegram и MAX: сообщения и картинки, отправленные в Telegram, появляются в чате MAX, и наоборот. Администратор группы может через Telegram ответить на вопрос, заданный в MAX, и ответ будет виден пользователям в обеих группах. Видно, кто написал сообщение, в каком чате и откуда пришёл ответ.

## Требования

- **Сервер и ОС:** Linux-сервер или виртуальная машина с возможностью установки Python 3.11+ и зависимостей. Предпочтительна Ubuntu Server LTS; для Windows-сервера можно выделить Linux-VM.
- **Ресурсы:** стартовый ориентир — 2 vCPU, 2 ГБ оперативной памяти и от 20 ГБ SSD, доступных приложению. Хранение SQLite — на локальном постоянном диске. Оценка уточняется по нагрузке и срокам хранения данных.
- **Входящие подключения:** публичный HTTPS на порту 443 для двух webhook-маршрутов. Допускается существующий reverse proxy с передачей запросов внутреннему приложению; отдельный публичный IP для приложения тогда не требуется. Доставка событий должна проходить без браузерной авторизации и CAPTCHA, с проверкой секретов webhook.
- **Адрес и TLS:** постоянный публичный HTTPS-адрес с доверенным сертификатом, полной цепочкой и автоматическим продлением. Можно использовать существующий домен заказчика и выделить два пути, например `https://example.ru/bridge/telegram` и `https://example.ru/bridge/max`. Отдельный поддомен, новый домен и сайт для участников не требуются, если администратор может направить эти пути к приложению.
- **Исходящие подключения:** HTTPS-доступ к API Telegram/MAX и файловым узлам обеих платформ. Прокси, фильтры и дополнительные сертификаты согласуются до установки.
- **Постоянная работа:** круглосуточный запуск моста и монитора, автозапуск после перезагрузки и восстановление после сбоя. Базовый вариант — службы systemd под отдельной учётной записью с ограниченными правами.
- **Настройка и секреты:** SSH-доступ по публичному ключу, при необходимости через VPN, либо установка администратором заказчика по инструкции. Токены ботов размещаются через согласованный защищённый канал, не включаются в Git и журналы. Закрытые SSH-ключи не передаются; администраторы сервера потенциально имеют доступ к секретам работающего приложения.
- **Сопровождение и данные:** назначенный администратор и получатель оповещений, согласованные сроки хранения переписки, правила доступа и удаления, резервные копии SQLite и проверка восстановления. Копии должны сохраняться отдельно от рабочего диска; действия с неопределёнными отправками выполняет назначенный оператор.

Соответствие существующего сервера проверяется до переноса. Разработка webhook, серверных служб и тестовое переключение выполняются по [плану размещения](SERVER-DEPLOYMENT-PLAN.md); наличие сервера не означает, что эти работы уже завершены.

Требования платформ к webhook сверены 21.10.2026: [MAX — HTTPS:443 и доверенный сертификат](https://dev.max.ru/docs-api/methods/POST/subscriptions), [Telegram — setWebhook](https://core.telegram.org/bots/api#setwebhook).
